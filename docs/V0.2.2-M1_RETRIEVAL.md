# V0.2.2-M1：Embedding 与混合记忆检索

基线：已合并的 PR #7（main 合并提交 `c429a3338a38c742efdd32e7dadd628f695428dc`）。Java21、Spring Boot4.0.8、Spring AI2.0.1 和 PostgreSQL17/pgvector 继续沿用。本次不调用真实模型、不部署、不开端口、不改正式业务数据、不建立 Live Baseline，Ubuntu 时钟问题仍待独立修复。

## 组件与边界

- `EmbeddingProvider`：可替换接口，模型 ID + 不可变版本，固定1024维；确定性 fixture 只在测试注册，不提供生产 MOCK 开关。
- `EmbeddingGateway`：查询和 L1 文本共用出站边界；DISABLED 默认阻断，LOCAL 仅 loopback，CLOUD 一律 EGRESS_DENIED。未来云端必须接入既有 ModelAuthorization（PrivacyGateway 职责），逐个 L0 来源及敏感权限核验，并增加查询文本的独立外发授权，不能仅换一个 Provider 绕过。
- `LocalEmbeddingProvider`：Spring AI OpenAiEmbeddingModel 适配已配置的 OpenAI-compatible `/embeddings` 服务；float 格式、不请求服务端降维，严格检查实际返回1024维、有限值和非零范数；不截断、不下载。禁用重试、代理和HTTP重定向。Spring AI2.0.1的传输定制器没有重定向选项，使用其 interceptor seam 提供禁止重定向的本地 OkHttp 传输，测试验证307不会转发。
- `EmbeddingService/Repository`：显式同步有界任务，生成在事务外，每条写回短事务锁 L1 + 修订 CAS。重复任务不调用已有同版本向量；并发任务可能重复计算，但只落一条向量。失败保留安全码，可重试补齐；进程崩溃的 RUNNING 任务需要人工识别，不具备后台调度/恢复机制。
- `RetrievalRepository`：关键词沿用分词/ILIKE，按命中词数排名；向量按余弦排名，最小相似度0.35。两路均先 SQL 过滤，候选池各100。
- `RrfRanking`：每个命中贡献 `1/(60+rank)`，相加后降序，同分按 UUID。KEYWORD/VECTOR 单路也返回对应的 rank-derived score；原始词数和余弦另列，不能把 RRF 当概率。
- 最终 L1 与证据装载再次 SQL 过滤；关联原始 sourceId、locator、role、occurredAt、excerpt，以及 L1 temporalScope 和 conflicts。未做“当前真相”推理，历史事实仍带原时间；矛盾记忆不覆盖。

## 本地模型配置（不会自动启用）

```dotenv
MIRROR_EMBEDDING_MODE=DISABLED
MIRROR_EMBEDDING_BASE_URL=http://127.0.0.1:8090/v1
MIRROR_EMBEDDING_MODEL=bge-m3
MIRROR_EMBEDDING_VERSION=unconfigured
MIRROR_EMBEDDING_API_KEY=
MIRROR_EMBEDDING_TIMEOUT=15s
```

仅在另行配置已存在的本地模型后，把 mode 改为 LOCAL，version 改成实际固定的模型/分词器/预处理版本（1–80个字母数字点横线下划线），不得以相同版本替换权重。ID最多100字符。Key只通过环境或受保护配置注入，不提交、不记录。模型若输出768/1536维会明确失败，本表固定1024，不能靠配置改维度。

loopback 指 **API进程所在网络命名空间**。Ubuntu Compose API 中的127.0.0.1不是 Ubuntu 宿主或另一普通容器；操作者须另行部署/配置与API共享网络命名空间的本地模型端点，或使用已有受控本地转发。不会自动添加模型容器、下载权重、启动Mac Docker或将模型/API/数据库端口暴露到校园网。Compose只追加环境变量透传，默认服务行为不变；本PR不执行部署。未来若支持私有网络端点，应单独设计可验证的网络授权，不能任意允许“LOCAL”指向公网。

应用配置关闭 `org.springframework.ai.openai.OpenAiEmbeddingModel` 日志（其TRACE可能输出输入）。不要启用模型/HTTP body TRACE、请求体日志或敏感 observation 采集。作业只存ID、模型版本、计数、固定错误码，无输入、向量、响应或异常正文。

## API（均沿用 X-Mirror-Token）

| 方法 | 路径 | 行为 |
|---|---|---|
| GET | `/api/v1/retrieval?query=...&limit=10` | 兼容原数组形状，默认HYBRID；不可用时关键词回退 |
| GET | `/api/v1/retrieval/explain?query=...&limit=10&mode=HYBRID` | KEYWORD/VECTOR/HYBRID，返回hits和评分/命中方式/状态/模型版本/耗时 |
| POST | `/api/v1/embeddings/jobs?limit=20` | 同步增量索引，limit1–100，不自动启动模型 |
| GET | `/api/v1/embeddings/jobs/{id}` | 仅当前owner的任务状态/计数/错误码 |
| POST | `/api/v1/ask` | 保留摘录式回答结构，使用相同检索，无生成模型 |

Explain的 `hits[].memory` 是原MemoryView，`methods` 为KEYWORD/VECTOR；分别给出keywordRank/keywordScore/vectorRank/cosineSimilarity、融合score。顶层 `vectorStatus` 为NOT_REQUESTED/READY/NO_MATCH或固定故障码（DISABLED/EGRESS_DENIED/UNAVAILABLE/DIMENSION_MISMATCH/INVALID_VECTOR）；模型不可用时即使请求VECTOR也回退关键词且明确标注。无向量命中时不替VECTOR模式造关键词结果，HYBRID始终含关键词一路。query1–1000字符，limit1–30。

任务状态 COMPLETE/PARTIAL/FAILED/BLOCKED；维度错误为failed + DIMENSION_MISMATCH。skipped表示计算后已过期或已由并发任务写入，不是新向量。批次不是原子事务，成功条目可保留，失败可增量重试。同步请求可能持续 limit×timeout；生产调用宜采用小批量。

## 生命周期与隐私

仅 ACTIVE / NORMAL / 至少一条仍可逐字验证的同owner PRIVATE user证据参与通用检索。拒绝、撤回、过期版本、待审核推断和敏感内容不会由旧向量复活。THOUGHT_PROCESS等仍须原有审核；审核通过后进入候选，需下一次显式增量任务。ACTIVE不代表时点仍为现在，不生成九维人格结论。

数据库触发器原子删除所有版本旧向量，修订CAS挡住在途结果。删除L0后沿用既有无证据L1清理；有剩余证据的L1保留，旧向量也失效。更新内容/类型/来源证据不会自动合并或覆写审核记录。模型版本切换仅读当前配置版本，旧版本隔离保留（生命周期变化时一起失效）；不自动清理旧版本，需将来单独授权的保留策略。

V3保留所有业务正文，只新增字段、作业表、触发器和版本化唯一索引，不修改V1/V2。正式迁移前须备份、评审触发器/索引锁开销、确认旧应用回退兼容；本次只在临时数据库验证。

## 离线复现与进入M2

见 [评估指南](../evaluation/README.md#v022-m1-检索离线基线)。报告为离线受控Mock基线，与Gold提取评估和首次DeepSeek观察记录隔离。生产本地模型尚未验收，真实召回率不可从Mock推断；精确向量扫描为O(N×1024)，且目前证据装载每条额外查询，小数据优先可解释性/权限正确性，扩展前需批量装载与真实规模压测。

M2应先在独立审核的检索集上评估真实本地Embedding的否定、时间、中文语义和多事实分辨，再加入显式时间过滤及证据支持检查；用RELATED_TO/CONTRADICTS输出可审核合并候选，保留来源/版本/撤回传播，禁止自动覆盖已审核记忆。大规模HNSW调优、异步索引调度、旧版本回收、模型工件签名、云端逐来源授权均留给独立任务。

参考：[Spring AI Embedding](https://docs.spring.io/spring-ai/reference/api/embeddings/openai-embeddings.html)、[pgvector余弦与过滤说明](https://github.com/pgvector/pgvector)。实现API按本仓库缓存的2.0.1源码核对，不随文档升级依赖。
