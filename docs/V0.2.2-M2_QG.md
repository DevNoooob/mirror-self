# M2-QG：记忆质量门禁、人工复核与本轮本地盲测

基于main `6cf4e82e9ae0ab4925024ee3e5352c9686467d96`。Mac开发、GitHub Actions隔离验证；Ubuntu真实模型执行仍需本轮独立授权。没有正式部署、业务库连接、生产V4执行、付费模型或校时。

## 人工复核入口

[76项完整审核卡](../evaluation/reviews/m2-qg-human/cards.md)按优先级展示v3全部45查询和M2-B全部31对：问题/双记忆、L0原文、role/owner/隐私、消息时间、L1时间范围、既有grade/关系/方向、理由及争议。优先五处grade2时间背景、R2Q11/23/42A/B、CC16及同义/矛盾/演化边界。

用户可在聊天逐条回复 `R2Q13: CONFIRM，理由…`，或复制 [决策模板](../evaluation/reviews/m2-qg-human/decisions-template.json)填写CONFIRM / CHANGE / DISPUTE；未提交项保持UNREVIEWED。CHANGE须提供新标签、方向和理由，DISPUTE可保留待决。模板的reviewer和reason须由实际用户填写。

```bash
python3 scripts/review-quality.py --validate /path/to/user-decisions.json
```

脚本只校验结构、输入SHA和逐项范围，不认证审核者身份、不自动修改参考、不将AI判断标为人工完成。当前所有项目仍未审。参考若获准修订，必须另立版本并保留v2/v3、旧Gold及原始报告。重新导出使用新目录；原目录仅允许相同字节重现。

## 固定输入、拆分与证据独立性

## 两阶段与门禁口径（运行前固定）

复用ConsolidationRecall、RetrievalRepository、现存向量、RRF、ConsolidationWriter、证据/状态审核。KEYWORD和HYBRID分别运行；向量路单独诊断，不用cosine代替关系分类。

- Candidate Recall：只问正确目标对是否进入Top10候选，另报Top3。pair口径为任一方向召回即命中；同时给每anchor查询Recall@10/@3，分母为2×正关系对数。纯向量Top10独立统计，未被RRF保留也可见；其失败与融合失败分开诊断。
- Relation Classification：只在实际召回候选上计算完整类型与方向的P/R/F1；正确类型但反方向同时记FP/FN，保守弃答记分类FN。另报端到端P/R/F1，召回未进入的目标只记召回FN，不归咎于规则或BGE以外的阶段。
- SAME_AS错误候选数单独硬门禁；无关关联率=错误无关关系/实际检查的无关候选对数（含弃答机会），分母另报，不能用正例大数量稀释。
- 证据正确率独立核对来源存在、owner、user、逐字quote及来源时间；它只证明溯源，不等于语义支持。无效语义证据对应参考NONE，任何错误关联同样触发零容忍门禁。
- owner/隐私违规按返回候选计数。每条已存候选仍应PENDING_REVIEW、RELATION_REVIEW_ONLY；同类型反方向审核以独立guard探针检验SUPPORTS/EVOLVED_FROM（素材取自固定输入，无额外Embedding），不混入候选P/R分母。
- 逐例JSON含keyword/vector/fused命中key、实际关系/方向、弃答码及CANDIDATE_RECALL / RELATION_CLASSIFICATION / FALSE_RELATION归因，所有弃答按原因列案例。

冻结标准：Candidate Recall@10≥0.90、完整关系P≥0.95/R≥0.80/F1≥0.85；错误SAME_AS=0、无关错误关系=0、owner/隐私/证据错误=0、审核策略及冲突审核正确率=1、provider失败=0。门禁文件及SHA不得按结果调低。

CI为观察模式：工具/回归测试可以通过，但质量报告可以明确FAIL。`--enforce`使任一数值门禁失败返回非零，不通过修改答案或断言隐藏问题。`v03Ready=false`仍受真实模型、独立人工参考审核和留出验收约束；CI绿灯不代表这些已完成。

## 方向冲突与V5

新增V5仅将候选幂等唯一键扩为包含direction；不重写现有行，不改V4。SUPPORTS/EVOLVED_FROM同类型反方向现在保留为两条不同假设，并显示RELATION_DIRECTION_CONFLICT；双向未决均不可批准。已有APPROVED保持原样，反向假设待审且阻断；显式拒绝竞争假设后才可继续，不自动翻转方向或改memory_relation。

候选创建/审核沿用双方L1顺序锁，批准SQL同时检查类型或方向不相同的有效非拒绝假设。V4→V5隔离升级测试核对旧批准行完整JSON不变。新唯一约束可能持锁与扫描索引，未来正式迁移须备份及独立授权；本轮没有正式Flyway执行。
