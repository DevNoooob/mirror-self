# 隐私与安全边界（V0.1）

## 已落实

- 所有 API（健康检查除外）使用 Owner Token 验证，时间安全字节比较；服务默认只监听 `127.0.0.1`。
- Docker Compose 仅发布 `127.0.0.1:8080/5432`，数据库具有独立密码；镜像运行非 root 用户。
- 主动关闭云端 AI 推理与 Embedding 外发；即使误设 `mirror.model-egress-enabled=true` 也拒绝启动。
- 所有读写 API 由服务端绑定固定 `owner_id`；检索在 SQL 层过滤 owner 和 ACTIVE 状态。
- 自动提取只来自 **user** 消息，不信任 assistant 消息中的人物推断。
- 模型推断与敏感候选必须审核；SensitiveDetector 仅初级防护，不能保证识别敏感数据。
- 删除 L0 来源时删除对应 evidence，没有其他证据的 L1 记忆硬删除，相关模型推断缺证据时清理。
- 不开放任何 share_profile / share_grant API；数据库中的表不代表功能已经获准上线。
- 审计仅记录实体 ID、操作类型和时间，不保存隐私正文。

## 未落实，因此禁止公网生产使用

- **没有 TLS/HTTPS、账号安全体系、令牌轮换 API、速率限制、CSRF/CORS 细化、登录设备管理**。
- 无端到端加密、字段加密、独立密钥管理、完整备份擦除机制。
- 无多租户 PostgreSQL RLS，单 owner token 不能用于第三方身份认证。
- 关键词隐私识别不能可靠发现 PII、健康/性取向/政治等敏感信息。
- 没有恶意 ZIP 解压机制（故只允许手工选取 JSON），对巨大畸形 JSON 仍可能有 CPU/内存压力。
- 不能证明从历史 L0 推导出的所有 L1/L2 都是正确的，务必核对 evidence。

## 后续 Privacy Gateway 必备检查

1. 已确认请求人和目标 owner 的身份，检索查询按权限过滤，禁止 LLM 决定授权。
2. 明确模型使用目的、将发送至哪一个提供商、是否允许该敏感等级出站。
3. 摘取最小必要上下文，必要时脱敏，并将出站文本/元数据可审计化。
4. 外部输入为不可信内容，不能通过“忽略以上规则”等提示词绕过授权。
5. 外发审批需要可撤销/可过期，重要消息/承诺/外部动作需要实际本人确认。

## 个人数据准备建议

真实 ChatGPT 导出包可能混有私人聊天、第三方信息和密钥。导入前建议先手动清理秘密信息，开启磁盘加密，并使用加密备份。切勿把 `.env`、真实 `conversations.json`、数据库卷或 `target/` 提交到 Git 仓库。
