# V0.2 第一阶段：有证据的智能记忆引擎

## 实际边界

复用 Java 21、Spring Boot 4.0.8、Spring AI 2.0.1、PostgreSQL 17/pgvector、Owner Token。
模型仅用于 L1 候选提取及独立的语义支持判断。没有工具回调，没有 Agent 框架，不更新 L2 人格或价值观画像。
原有导入、检索、手工记忆、审核、删除和本地摘录式问答接口保留。
为避免破坏既有构建脚本，本次保留 Maven `0.1.0-SNAPSHOT` 制品名称；功能版本为 V0.2 第一阶段。

## 最终链路与职责

```text
ChatGptDecoder（保留全部原始消息、角色、时间、父子关系）
  → SourceRepository（L0 先独立提交、保持原有定位符及 JSON 哈希去重）
  → 按 current_node 父链提取；未指定时按各叶子路径独立处理
  → MemoryExtractionService（记录任务，按角色上下文分批，模型 I/O 不持有事务）
      → RULE: RuleBasedExtractor / LLM: LlmMemoryExtractor
      → ModelAuthorization（全局开关 + 来源/提供商/模型绑定 + 到期/撤销 + 敏感授权）
      → SpringAiModelGateway（真实 Spring AI OpenAiChatModel，无工具，store=false，超时，无应用重试）
      → 严格 JSON 字段、类型、长度、枚举、深度、重复键及尾随数据检查
      → MemoryValidator（重查 owner 的真实来源、user 角色、原文与本批发送片段逐字匹配）
      → LLM 独立语义支持检查（问题/假设/建议/第三人引用/历史限定语不构成直接事实）
      → MemoryService（事务内重验原文、分级、去重、证据入库、基础冲突标记）
      → memory_item + memory_evidence + memory_relation
  → ACTIVE 记忆及原始证据检索
```

模型输出是未信任的数据。全部历史消息作为带角色标签的 JSON 数据提供，历史 system/tool 文本也不能成为新的系统指令。
系统提示、JSON Java 校验、真实 L0 查询、云端授权和数据库权限不由模型决定。

## 候选、证据及时间契约

模型返回 `{"memories":[...]}`，每项必须且只能含：

```json
{
  "type":"OPINION",
  "content":"我以前认为咖啡不好",
  "origin":"USER_EXPLICIT",
  "sensitivity":"NORMAL",
  "temporalScope":"HISTORICAL",
  "evidence":[{"sourceId":"11111111-2222-4333-8444-555555555555","quote":"我以前认为咖啡不好"}]
}
```

- 沿用 `FACT/EVENT/KNOWLEDGE/OPINION/GOAL/THOUGHT_PROCESS`，偏好使用 OPINION。
- 明确表达的 `content` 必须与某条 user 引用完全一致，且引用不能截去句子的开头/限定语；问题及简单附和不自动入库。
  这是本阶段刻意保守的约束：LLM 选择、分类和理解多轮上下文，但明确事实暂不允许自由改写。
- MODEL_INFERRED 仅允许 THOUGHT_PROCESS；必须有实际 user 原文支持，且独立语义验证通过，仍然进入待审核。
  `OBSERVED` 枚举保持兼容，LLM 不允许自行使用。
- 所有证据必须同时存在于指定 owner 的 L0 消息及本批发送片段，不接受 assistant/system/tool 作为个人断言证据。
- 语义验证返回每项索引及严格布尔值；遗漏、重复、越界或格式异常均拒绝该批。
- `occurredAt` 由服务端取直接证据消息时间，表示**表达时间**，不是模型编造的事件发生日期。
  `SOURCE_TIME` 表示仅在该消息时点成立的表达，不能解释为现在仍成立；`HISTORICAL` 保留明确的过去观点/经历。
  每条 evidence 同样返回各自时间。合并重复表述不会丢失来自不同时间的证据。
- 无效结果只记录任务 ID 与固定错误码，不记录原文、模型原始响应、密钥或异常 cause。

## 分级、去重和冲突

| 候选 | 初始状态 |
|---|---|
| 可验证的普通明确事实、事件、知识、偏好、观点、目标 | ACTIVE |
| THOUGHT_PROCESS，包括用户对性格/价值观的自述 | PENDING_REVIEW |
| MODEL_INFERRED | PENDING_REVIEW |
| SENSITIVE / SECRET | PENDING_REVIEW，永不自动写入 L2 |
| 无法验证、语义拒绝、非法 JSON | 不写入 |

本地词表扫描候选与其完整来源，只能提高敏感等级，不能降低；手动记忆也执行此检查。
词表不是完整的 PII/秘密识别能力，云端发送前仍需本人检查实际上下文。

相同导出原文再次导入会跳过已存在来源的自动提取；如需重新处理，显式调用重提取接口。
明确记忆使用 NFKC、大小写、空白和末尾标点规范化做确定性去重，并能识别 V1 旧 dedupe_key 的等价文本。
推断额外使用类型、origin 及排序后的 sourceId/精确 quote 指纹，阻止同一证据的改写不断新增候选。
拒绝的记忆不会因重提取重新激活；新证据仅追加，原内容、审核决定及来源时间不被覆盖。
同一 owner 的写入使用事务级 advisory lock，避免并发规范化去重与冲突检测竞态。

复用 `memory_relation.CONTRADICTS`，目前只检测明显的“喜欢/不喜欢同一对象”和不同居住地；返回 `conflicts` ID。
这只是潜在矛盾提示，可能是时间演变，保留两条记录及时间，不覆盖旧记录，不保证发现所有矛盾。
复杂语义整合、跨语言同义合并和认知演化尚未实现。

## 隐私、配置与授权

| 环境变量 | 默认值 / 用途 |
|---|---|
| MIRROR_EXTRACTION_MODE | RULE；可设 LLM |
| MIRROR_LLM_MODEL | 空；LLM 模式必填，使用提供商实际支持的名称 |
| MIRROR_LLM_BASE_URL | https://api.openai.com/v1；OpenAI-compatible 根地址，带 /v1 |
| MIRROR_LLM_API_KEY | 空；从环境或安全配置注入 |
| MIRROR_LLM_LOCAL | false；true 只接受 loopback 地址 |
| MIRROR_MODEL_EGRESS_ENABLED | false；云端调用全局开关，不代替逐来源授权 |
| MIRROR_LLM_TIMEOUT | 30s，每次模型请求超时，最大120秒 |
| MIRROR_LLM_BATCH_CHARS | 16000，保守估算转义后 JSON 上下文字符预算，1000–100000 |
| MIRROR_LLM_BATCH_MESSAGES | 30，单批消息片段上限，2–100 |

批处理以保守字符预算限制输入，不能等价于所有模型的 token 限制；还需为系统提示、候选验证和输出保留上下文空间。
长消息按带重叠的片段处理，批次间最多携带前两条消息，引用仍使用原 sourceId。
超长且无法保留完整断言的片段可被拒绝，允许少生成，不能为了覆盖率虚构记忆。
每批通常需要两次模型调用（提取 + 语义校验）；每次最多20候选、每候选最多8证据。

本地模型示例（主机运行 API）：

```bash
export MIRROR_EXTRACTION_MODE=LLM
export MIRROR_LLM_LOCAL=true
export MIRROR_LLM_BASE_URL=http://127.0.0.1:11434/v1
export MIRROR_LLM_MODEL='你已安装的本地模型'
# MIRROR_LLM_API_KEY 可空；本地服务必须由你信任，不能是未经授权的云端代理。
mvn spring-boot:run
```

容器中的 loopback 指容器本身。Compose API 若要访问主机上的本地模型，需要自行配置受控部署网络；
当前 local=true 刻意不接受任意内网地址，不能直接用 host.docker.internal 冒充本地授权。
规则模式与本地模式均不需要云端 grant。云端模式同时要求全局开关及对所有实际发送来源（包括 assistant）的授权。
授权绑定当前配置的 endpoint + model，最长24小时，可撤销；更换提供商或模型后旧授权失效。
普通授权不包括检测到的敏感来源；allowSensitive=true 才可发送 SENSITIVE；检测到的 SECRET 或 L0 RESTRICTED 始终拒绝。
不会在失败时静默切换到其他模型，也不自动扩大授权范围。启用全局开关本身不会发送数据。

## API 使用

所有接口都要求 `X-Mirror-Token`，owner 由服务端固定绑定，不接收客户端 ownerId。

| 方法 / 路径（前缀 /api/v1） | 行为 |
|---|---|
| GET /sources?limit=100&offset=0 | 分页列举来源元数据、节点及父节点 ID，不返回原文 |
| POST /extractions | 同步执行指定一条对话/分支的提取，返回可查询任务 |
| GET /extractions/{id} | 查看状态、计数、错误码、来源 ID、模型及提取器版本 |
| POST /model-egress-grants | 显式授权选定来源发送给当前配置的提供商/模型 |
| DELETE /model-egress-grants/{id} | 撤销授权 |
| POST /memories/{id}/review | 沿用 V0.1：APPROVE / REJECT |

`GET /sources/{id}` 可核对原文；最多选择500个来源重新提取。父链会排序，不允许同一请求混入不相关对话或不同分支。
缺少父链时按已知消息时间排序，缺少时间时保留请求顺序，无法重建缺失的上下文。

云端完整操作：

1. 配置 LLM、密钥及全局开关，导入文件。L0 会保存，未授权的提取任务返回 BLOCKED。
2. 调用来源列表，检查原文，选定一条对话/分支的实际来源。
3. 设置实际未来的 ISO-8601 到期时间（24小时内），创建 grant：

```bash
curl -sS -X POST http://127.0.0.1:8080/api/v1/model-egress-grants \
  -H "X-Mirror-Token: $MIRROR_OWNER_TOKEN" -H 'Content-Type: application/json' \
  -d '{"sourceIds":["实际-user-来源UUID","实际-assistant-来源UUID"],"expiresAt":"实际未来时间","allowSensitive":false}'
```

4. 使用返回的 `id` 调用：

```bash
curl -sS -X POST http://127.0.0.1:8080/api/v1/extractions \
  -H "X-Mirror-Token: $MIRROR_OWNER_TOKEN" -H 'Content-Type: application/json' \
  -d '{"sourceIds":["实际-user-来源UUID","实际-assistant-来源UUID"],"grantId":"实际-grant-UUID"}'
```

规则/本地模型重提取可以省略 grantId。以上 UUID 和到期时间为需要替换的字段，不是可直接执行的数据。

任务状态：COMPLETE（所有批处理成功）、PARTIAL（至少一批已处理且有拒绝/失败）、FAILED（无批处理成功）、BLOCKED（未授权）。
`acceptedCount` 是通过验证的候选数量，可包含因重叠或已存在而去重的候选；`newMemories` 才是新增行数。
导入返回字段 `jobId/importedSources/existingSources/newMemories` 保留，另增 `extractionJobIds`。
导入 COMPLETE 仅表示 L0 导入完成，必须检查关联 extraction job；不要把 HTTP 200 或零新增当作模型验证通过。
已有来源重复导入不会自动重试旧失败任务，使用 GET /sources + POST /extractions 明确重试。

读取 memory/retrieval/ask 的证据对象保持原字段，并增加 `temporalScope/extractorVersion/modelId/conflicts`。
新增任务接口为同步有界请求，未引入后台 worker。进程在执行中终止时 RUNNING 任务暂需人工判断并重新提取，尚无自动租约恢复。

## 事务与数据库升级

仅新增 V2，V1 文件不改；新增 extraction_job、extraction_job_source、model_egress_grant、model_egress_grant_source，
并为 memory_item 添加可空追踪字段、语义时间范围及去重索引。旧数据读取兼容，旧模型追踪字段可为 null。
完整原文先提交；模型调用不占用事务；通过验证的单批记忆、证据、冲突及审计在一个事务内原子提交。
一个批次失败时该批回滚，之前批次保留并以 PARTIAL 暴露，不执行清库或 destructive reset。

```bash
mvn test

python3 scripts/validate_structure.py
bash scripts/smoke-domain.sh
```

真实模型 smoke 独立开启，全部使用虚构数据，也可能产生费用；不会在默认测试中调用：

```bash
# 先在环境中设置 MIRROR_LLM_MODEL / MIRROR_LLM_BASE_URL / MIRROR_LLM_API_KEY
MIRROR_RUN_LIVE_LLM=true mvn -Dit.test=LiveModelIT verify
```

未实现：任意自然语言事实蕴含的形式化证明、可靠敏感信息识别、复杂语义去重/冲突、后台调度恢复、向量生成、L2 自动建模与九维人格模拟。
两次 LLM 调用不是两个独立模型，不构成正确性保证；确定性引用校验与人工审核仍是边界。
真实模型的支持能力及提取质量需要使用选定模型实际验收，不能用 Mock 测试替代。
