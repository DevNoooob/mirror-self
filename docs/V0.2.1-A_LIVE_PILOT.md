## 已检查的实现与最小改进

继续使用原有 Spring AI SpringAiModelGateway 和 deepseek-flash。没有新增模型 SDK、评估引擎、HTTP API 或数据库迁移，也不更新正式服务。

- 原网关仍在调用前执行 ModelAuthorization，设置 store=false、toolChoice=none、maxRetries=0；诊断只含异常类型/HTTP 状态/耗时。API Key 只从安全环境注入，本阶段不读取密钥文件或运行模型探测。
- 来源级 grant 仍绑定 owner、endpoint+model、消息和过期时间；授权包括发送的 assistant 上下文，但记忆证据只能来自 user。独立测试数据库限制继续有效。
- Live 必须给出 requested case IDs 与独立 approved case IDs，集合一致且无重复/未知值；缺失时拒绝，避免误跑 66 例。普通离线模式不受此限制。
- 显式 review attestation 和数据 SHA 是两层校验；attestation 仅记录操作者声明，不由 AI 生成审核结论。
- 评估网关按批准调用限额先预留配额再委托原网关，超额用固定 EGRESS_DENIED 阻断，报告 budgetDenied。超额后报告保留，但运行失败，不能当完整基线。
- Report 1.1 增加候选审计：阶段、索引、TP/FP/Pending、相关 Gold ID、类型/来源/时间/状态、选中消息及 UTF-16 位置。**不包含候选正文、quote、原始响应或推理**，未知引用显示 unknown。
- 原 metricVersion 和匹配口径保持不变；1.0 旧报告仍可读取比较。Pending 无法仅靠审计元数据完成语义人审，需要另行授权的受控查看，不能凭空给出最终准确率。

当前进程未从 `.env` 或密钥文件加载真实配置；文档中的 endpoint/model 为拟议运行目标，不是已经联网验收的声明。Spring 绑定仍是 MIRROR_LLM_BASE_URL / MODEL / API_KEY → ExtractionProperties → 原网关。

## MQ045 修复与保留的边界

按用户回复要求，仅修复生产 MemoryValidator 对 **后接空白的 ASCII 句号** 的起句识别；保留否定、角色、全文引用、历史限定语和语义验证。小数内部句点、姓名首字母和常见英文缩写不被新增为边界。不会为了适配 MQ043 语义别名放松 USER_EXPLICIT 逐字校验。

Prompt 没有变更。LLM 提取器版本的 validator 后缀升级至 validator2，规则流水线也标记 validator2。新增单元测试直接运行真实 validator，不需要模型或数据库。

其他问题仍保留供真实验收：MQ022 的个人条件意向与现有 hypothetical 排除规则有冲突；MQ032 相对过去表达未被确定性关键词完整覆盖；MQ047 若上游错误标成 FACT，MemoryPolicy 仍依赖类型并可能 ACTIVE。不能把未调用的语义模型假定为已兜底，更不能由 Mock 推算真实发生率。

九例全部是普通授权场景；MQ047 是 USER_EXPLICIT 人格自述。此批不能覆盖真正的 MODEL_INFERRED、敏感授权、无 grant、SECRET 或 RESTRICTED 的全部行为；这些仍由离线回归覆盖，下一轮需另行审查更多虚构案例。

## 拿到实际 Live 后的质量分析

使用 [分析模板](../evaluation/reviews/live-analysis-template.md)，所有目前未测量项都留为待测：

1. 从 EXTRACTION counts 计算确认 TP/FP/FN/Pending 与 P/R/F1 分子分母；与 PERSISTENCE 分开，Pending 是保守下界，不伪装为已确认 FP。
2. 分别汇总 EVIDENCE_VALIDATION、SEMANTIC_VALIDATION 的拒绝数；这些只对应首轮候选，modelCalls 还包含重放。
3. 将候选审计 stage/index/referenceMemoryId 与 VALIDATOR_REJECTION 关联：原始 TP 且被拒绝才是可定位的漏记候选；未生成 Gold、未知改写和重复去重分别处理。
4. 检查 assistant/第三人归因、历史范围、MQ047 审核状态、预算与来源授权；只对九例覆盖范围给结论，不声称“没有任何隐私风险”。
5. Prompt：关注个人条件意向 vs 纯假设、类型口径和输出粒度。Validator：关注逐字约束取舍、混合句界与相对时间漏检。MemoryPolicy：区分正确类型下分级与上游错分类造成的后果，不能用一次模型输出断言因果。
6. 操作失败、超额、格式错误、被跳过或数据摘要不一致时，不建立“可信完整基线”。不能拿 Mock 成绩代替 DeepSeek 成绩，不按模型答案改 Gold。
