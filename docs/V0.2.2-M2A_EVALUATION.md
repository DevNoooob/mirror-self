## 证据判断接口

`EvidenceSupportJudge` + `ConservativeEvidenceJudge`（当前版本evidence-rules-1.1，首次真实运行使用evidence-rules-1）是独立、无写入、无模型调用的Java接口，评估时消费已通过SQL权限和逐字证据过滤的MemoryView。暂不增加HTTP接口，不改变 `/ask` 格式和行为。离线结果不自动确认人格、不写入memory_relation或覆盖记忆。

| 关系 | 含义 |
|---|---|
| SUPPORTS | 指定时间范围内的用户原始引用直接支持被检验命题 |
| REFUTES | 指定时间范围内直接反驳命题；属于相关证据 |
| RELATED_ONLY | 仅有主题/条件/自述等关联，不能直接证明该命题 |
| INSUFFICIENT_EVIDENCE | 无有效证据、规则无法建立支持关系，或结论存在未解决冲突 |

问题先解析为subject / predicate / object / polarity / requestedTime / explicitYear；“我喜欢重复劳动吗？”测试肯定命题，“我不喜欢重复劳动吗？”测试否定命题。证据“我不喜欢重复劳动”分别REFUTES和SUPPORTS。依据是L0 quote，不能用L1改写或cosine当作蕴含判断。

初版只支持少量通用中英文语法及常见词等价（如coffee/咖啡、gardening/园艺），不是通用NLI。未知改写、多事实、双重否定和过长引用采取保守弃答。条件GOAL不变成决定/完成事件；自我评价只能支持“用户这样评价自己”，不能证实客观人格。助手引用、无证据、待审核或敏感记录不提供直接判断。接口本身没有owner字段，必须由已完成owner权限过滤的检索调用方提供MemoryView；评估仍逐条复核owner和L0。

每条Decision返回sourceIds、实际判断、sourceTimeRelation、evidenceTimeScope、currentRecognition=UNCONFIRMED及固定原因码，不返回推理链，不使用参考答案决定关系。聚合同时存在支持与反驳、或仅召回一侧但已有冲突标记时保守返回INSUFFICIENT_EVIDENCE，不按排名/时间静默选择“最新真相”。

## 时间语义

- HISTORICAL：原文描述过去发生/成立；不自动投射现在。
- SOURCE_TIME_ONLY：只在原始消息时点陈述，不等于用户现在仍认可。
- CURRENT：显式“现在/目前/still”等问题；仅有旧SOURCE_TIME/HISTORICAL时RELATED_ONLY，原始时点极性保存在sourceTimeRelation，当前结论不足。
- 相对时间或不匹配年份不猜测；明确年份需与原文对应。
- CONTRADICTS标记表示已有相反证据；历史记录仍保留。没有额外认可、修订事件和精确时间上下文，就不宣称哪条现在有效。保守聚合可能错拒有效历史/修订证据，单独记录为判断器问题。

## 指标与错误归因

三路复用现有EmbeddingProvider、RetrievalService、pgvector SQL和RRF（候选100/路、常数60、余弦阈值0.35、K=3），不按真实结果调参。

- Recall@3 / MRR / nDCG@3：有参考相关记忆的查询宏平均，SUPPORTS和REFUTES都算相关。
- Precision@3：前三个槽位的相关条数/3，短结果仍用3作分母；在正例查询宏平均，和正确空集率分开。含4条相关记忆的组合问题Recall@3理论上限为3/4。
- 正确空结果率：无参考相关项的查询实际返回空的比例。返回别的owner/拒绝/待审/敏感项另算隐私违规，不能把“普通误召回”都称为越权。
- 证据正确率：核对实际sourceId、user角色、同owner和原始逐字引用；引用正确不代表语义相关或支持命题。
- relationAccuracy：所有返回结果与独立关系标注比较；未列入参考的结果默认为INSUFFICIENT_EVIDENCE，参考不完备是人工复核风险。
- supportsRefutesAccuracy：只在实际召回且参考标注为SUPPORTS/REFUTES的直接证据对上计算。同步报告directTotalRetrieved、referenceDirectTotal、endToEndDirectRecall，避免少召回得到虚高关系准确率。
- oracleJudge：给判断器完整参考证据集合的独立评估，用于把检索遗漏与判断器能力分开；不作为检索成绩。
- 聚合准确率、错误支持/反驳、时间越权、missedReferenceIds/extraIds逐例列出。
- p50/p95：System.nanoTime计时，包含SQL、本地查询Embedding与结果装载，不含证据判断；每查询重复3次，暖身计调用数但不计延迟。数据量小，不代表生产吞吐。

报告标注真实/哈希fixture条件，绝不混用。Ubuntu墙钟未验证，UTC字符串仅为未验证观测；时长使用单调时钟，Mac接收时刻与代码SHA另外记录，不自动校时或冻结正式Live Baseline。

## 首次真实结果与修复重放

真实本地调用298次，完整原始报告和错误分析见 [首次BGE观察](../evaluation/runs/bge-m3-v2-first/analysis.md)。VECTOR Recall@3=0.9414，HYBRID=0.9009；两者正确空集均0/7，不能直接作为回答或自动整合依据。首次聚合存在“无关冲突否决直接证据”的过度弃答，已以1.1契约离线修复重放；真实检索分数与原始报告不改，不重新调用模型。

容器化Ubuntu复现可由宿主Python预检，再用已有Maven21镜像以host network运行同一verify命令（只挂载临时checkout和Docker socket；不开API服务；Ryuk禁用时须按本次唯一标签兜底清理）：

```bash

MIRROR_RUN_LOCAL_RETRIEVAL=true \
MIRROR_APPROVED_RETRIEVAL_DATASET_SHA=4b0cde4f771356ea86c2bf70cfab27703c7bf7d06bbebb7acd308482526f2ad4 \
MIRROR_APPROVED_RETRIEVAL_REFERENCE_SHA=cd1c9933d61460657eaed2247b490ae502bc7fc7dbccbce8a0ffc1e83f1285b2 \

mvn --batch-mode --no-transfer-progress -Dtest=EvidenceSupportJudgeTest,RetrievalCorpusTest -Dit.test=LocalBgeRetrievalIT verify
```
